# 🪫 DTEK Monitor

Автоматичний моніторинг планових та аварійних відключень електроенергії від ДТЕК зі сповіщеннями в Telegram.

## 💖 Підтримка

Якщо проєкт корисний для вас не забудьте поставити ⭐️ та [підтримати донатом](https://send.monobank.ua/jar/3QTpZrNn2T).

## 📋 Опис

Проєкт автоматично перевіряє інформацію про відключення електроенергії на сайті ДТЕК для вказаної адреси та відправляє сповіщення в Telegram при виявленні відключень. Моніторинг запускається кожні 10 хвилин у Docker (планувальник supercronic, див. [README-DOCKER.md](README-DOCKER.md)). GitHub Actions workflows залишено лише для ручного тестового запуску.

## ✨ Можливості

- 🤖 Автоматична перевірка статусу електропостачання кожні 10 хвилин.
- 🌅 Щоденне ранкове повідомлення з інформацією про планові відключення (приблизно 02:10–03:10 за Києвом на GitHub Actions, 00:05 у Docker).
- 📱 Надсилання сповіщень в Telegram про відключення.
- 💬 Окремі повідомлення для кожної події: нове відключення, відключення минуло, відключення скасовано, екстрене відключення.
- 🔄 Після кожного повідомлення — тихе повідомлення «Остання перевірка статусу: HH:MM», яке редагується при кожній перевірці без змін. При новому оновленні попереднє таке повідомлення видаляється, тож воно завжди одне й останнє в чаті.
- 📊 Відображення причини, часу початку та очікуваного часу відновлення.
- 🔄 Автоматичний запуск у Docker (supercronic).

## 🚀 Швидкий старт

### 1. Форк репозиторію

Натисніть кнопку "Fork" у правому верхньому куті сторінки репозиторію.

### 2. Створення Telegram бота

1. Відкрийте [@BotFather](https://t.me/BotFather) в Telegram.
2. Відправте команду `/newbot`.
3. Вкажіть ім'я та username для бота.
4. Збережіть отриманий токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### 3. Отримання Chat ID

1. Відправте будь-яке повідомлення вашому боту.
2. Відкрийте в браузері `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`.
3. Знайдіть значення у форматі `"chat":{"id":123456789}` — це ваш Chat ID.

### 4. Налаштування Secrets

Перейдіть в **Settings** → **Secrets and variables** → **Actions** вашого форкнутого репозиторію та додайте наступні secrets:

| Secret | Опис | Приклад |
|--------|------|---------|
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather | `123456789:ABCdefGHI...` |
| `TELEGRAM_CHAT_ID` | ID чату в Telegram | `123456789` або `-123456789` (для каналу) |
| `CITY` | Місто кирилицею | `Васюківка` |
| `STREET` | Вулиця кирилицею | `Перемоги` |
| `HOUSE` | Номер будинку | `1` |

> PAT не потрібен: workflow моніторингу лише читає репозиторій (вбудований `GITHUB_TOKEN` з правом `contents: read`) і нічого в нього не комітить.

### 5. Запуск Actions

1. Перейдіть на вкладку **Actions**.
2. Активуйте workflows натиснувши **"I understand my workflows, go ahead and enable them"** (якщо потрібно).
3. Знайдіть та відкрийте workflow з назвою **"Run power outages monitor"** для тестового запуску.
4. Праворуч вгорі натисніть **Run workflow** → і ще раз на **Run workflow** всередині випадного меню.

> ⚠️ **Увага:** розклад обох workflows (**Run power outages monitor** і **Daily morning summary**) вимкнено - основний спосіб запуску тепер Docker (див. [README-DOCKER.md](README-DOCKER.md)). На GitHub Actions стан (`artifacts/message-history.json`) не зберігається між запусками, тому якщо увімкнути розклад моніторингу, сповіщення про те саме відключення надсилатимуться повторно, а повідомлення «відключення минуло» / «відключення скасовано» не працюватимуть. Ручний запуск workflow - лише для тестування.

## 🛠 Локальний запуск

### Вимоги

- Node.js (версія вказана в `.nvmrc`)
- npm або yarn

### Встановлення

```bash
# Клонування репозиторію
git clone https://github.com/YOUR_USERNAME/dtek-monitor.git
cd dtek-monitor

# Встановлення залежностей
npm install
# або
yarn install
```

### Налаштування

Створіть файл `.env` в кореневій директорії (скористуйтесь `.env.example`) з вмістом такого штибу:

```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-12346789
CITY=Васюківка
STREET=Перемоги
HOUSE=1
```

### Запуск

```bash
# Перевірка відключень (основний моніторинг)
node monitor.js

# Ранкове повідомлення (автоматично: ~02:10–03:10 за Києвом на GitHub Actions, 00:05 у Docker)
node daily-summary.js

# Юніт-тести (monitor.test.js, daily-summary.test.js, dtek.test.js)
npm test
```

Для кожного PR у `main` тести запускаються автоматично (`.github/workflows/test.yml`). Перевірка `npm test` обов'язкова: поки вона не пройде, merge заборонено (branch protection для `main`).

Допоміжні debug-скрипти знаходяться в директорії `scripts/` (вони відкривають реальний сайт ДТЕК і не входять до `npm test`).

### Dev-залежності для scripts/

Скрипти в `scripts/` використовують Playwright (devDependency) і не потрібні для продакшн-запуску. Перед їх використанням виконайте `npm install` і:

```bash
npx playwright install chromium
```

## 🔍 Як це працює

1. **Отримання інформації**: Скрипт використовує `impit` (HTTP-клієнт з TLS-відбитком Chrome) і `tough-cookie` (cookie jar) без запуску браузера: зчитує CSRF-токен зі сторінки ДТЕК і виконує AJAX-запит з вказаною адресою.
2. **Перевірка відключень**: Аналізуються дані про наявність відключень (причина, час початку, час завершення). Екстрене відключення визначається за блоком `#modal-attention` на сторінці, текст якого містить стем `екстрен` (без урахування регістру).
3. **Відправлення повідомлення**: При виявленні відключення формується повідомлення та відправляється в Telegram.
4. **Окремі повідомлення**: Для кожної події надсилається нове повідомлення: нове відключення, відключення минуло, відключення скасовано, екстрене відключення. Слідом надсилається тихе повідомлення з часом останньої перевірки (попереднє видаляється); поки змін немає, бот лише оновлює в ньому час (його `message_id` зберігається в `statusMessageId` у `artifacts/message-history.json`).
5. **Збереження стану**: Останнє надіслане повідомлення зберігається у `artifacts/message-history.json` лише там, де працює скрипт (у Docker - у bind mount `./artifacts` на хості). Файл не відстежується git і не комітиться в репозиторій.

## ⚙️ Налаштування

### Зміна частоти перевірки

Відредагуйте cron-вираз у файлі `crontab` (Docker/supercronic) і перебудуйте образ (`docker compose up -d --build`):

```
*/10 * * * * cd /app && node monitor.js
```

Приклади:

- `*/30 * * * *` - кожні 30 хвилин
- `0 * * * *` - щогодини
- `0 */2 * * *` - кожні 2 години

### Додавання декількох адрес

Для моніторингу декількох адрес створіть окремі репозиторії або дублюйте workflow з різними secrets.
